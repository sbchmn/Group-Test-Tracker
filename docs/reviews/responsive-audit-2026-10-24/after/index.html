F1. New payment report

A new report opens normally with several methods and no saved selection. Submit stays disabled until a method is selected. Failed loading hides decision controls.

Both configuration forms render live optional/either/all summaries. Missing optional helper markup cannot abort other script initialization.

Configured destinations and the Payment Matrix adapt to available space. Edit remains visible; secondary actions are in More.

F4. Manage Users

Identity and status fields remain visible in cards when the table will not fit. Reset and activation actions are grouped under More. The managed support form stacks on phones.

F5. Tags

Rename fields use the card width instead of shrinking to a few pixels. Merge stays visible; other actions are grouped. Duplicate and retired-tag tables also reflow.

F6. Action Queue

Both queue sections adapt to their container. Primary review/approval actions remain visible. Join-request selection, counts, bulk forms, filters and pagination are preserved.

F7. Bot Command Registry

Saved commands use readable cards when needed, with Edit and More controls. Long reply previews expand within the current page.

F8. Test-detail participant list

The participant list occupies a full-width section, with readable cards on smaller screens and a table when it fits. Narrow payment panels stack QR previews beneath the destination.

F9. Result Analysis Review

Each finding has a labelled acceptance control, a full-width result input, readable evidence and its state on narrow screens.

F10. Headers and action spacing

Header actions move to their own row on small screens. Shared gaps and tap targets replace incidental wrapping. Quick result-link forms also stack on phones.
